# 快速开始

> **这是一份说明文档，不是程序。** 双击会用你机器上的 Markdown 编辑器打开（VSCode / Typora / WorkBuddy 等），
> 读它就行，**不会执行任何东西**。
>
> **真正的安装动作是双击包根目录的 `安装.bat`。**

目标：15 分钟内让 AI 能读写你的博途工程。

---

## 第 0 步：确认前置条件

在 PowerShell 里跑这条，看当前用户在不在 Openness 组：

```powershell
whoami /groups | Select-String "Openness"
```

- 有输出 → 通过
- 没输出 → 加组：`计算机管理 → 本地用户和组 → 组 → Siemens TIA Openness → 添加 → 输入你的用户名`
  然后**注销重登**（不重登不生效）

---

## 第 1 步：解压 + 安装

1. 解压到固定位置，例如 `D:\TIA-MCP\`，**路径不要含空格**
2. 双击 `安装.bat`
3. 看到 `安装完成（11 项自检全过）` 就对了

安装脚本（`install.js`）做了三件事：
- 把 `skills/` 下六个 skill 同步到 `%USERPROFILE%\.agents\skills\` 及本机已检测客户端的 skills 目录（Antigravity 的 `%USERPROFILE%\.gemini\config\skills\`、WorkBuddy 的 `%USERPROFILE%\.workbuddy-ai\skills\`、Claude Code 的 `%USERPROFILE%\.claude\skills\`）
- **安全探测并幂等合并 MCP 配置**到本机已装的 **10 类主流 AI 客户端**（仅更新指向不同路径的旧条目，路径已一致则跳过且不产生多余备份，改前自动备份 `.bak-时间戳` 并保留原有 `env`）
- 在 `生成的配置/` 下留齐全部 10 份配置模板与 `使用说明.txt`，方便未自动安装的客户端按需手动配置

> 高级用法（命令行）：
> - `gateway\runtime\node.exe install.js --list`（只读查看 10 类宿主探测与配置状态）
> - `gateway\runtime\node.exe install.js --dry-run`（预演全部变更，不改任何文件）
> - `gateway\runtime\node.exe install.js --configs-only`（仅刷新 `生成的配置/` 下模板与说明，不改用户目录 skills 或宿主配置）
> - `gateway\runtime\node.exe install.js --host cursor,vscode --update`（指定宿主写入或强制更新）

---

## 第 2 步：安装脚本已经帮你配好了

**这一步通常不用做任何事。** `安装.bat` 会自动探测本机已装的客户端并安全合并配置（不会在未安装的客户端上强行建空文件）：

| 客户端 (`--host`) | 配置文件位置 | 写入格式 / 行为 |
|---|---|---|
| **Antigravity** (`antigravity`) | `%USERPROFILE%\.gemini\config\mcp_config.json`（兼容旧版 `.gemini\antigravity\mcp_config.json`） | 合并 `mcpServers.tia-gateway`，同步 skills |
| **Gemini CLI** (`gemini-cli`) | `%USERPROFILE%\.gemini\settings.json`（仅该文件存在时探测） | 合并 `mcpServers.tia-gateway` |
| **Claude Desktop** (`claude-desktop`) | `%APPDATA%\Claude\claude_desktop_config.json` | 合并 `mcpServers.tia-gateway` |
| **Claude Code** (`claude-code`) | `%USERPROFILE%\.claude.json`（仅在 `.claude.json` 或 `.claude` 目录存在时探测） | 合并 `mcpServers.tia-gateway` |
| **Cursor** (`cursor`) | `%USERPROFILE%\.cursor\mcp.json` | 合并 `mcpServers.tia-gateway` |
| **VS Code** (`vscode`) | `%APPDATA%\Code\User\mcp.json` | 合并 `servers.tia-gateway`（`type: "stdio"`） |
| **Codex** (`codex`) | `%USERPROFILE%\.codex\config.toml` | 更新 `[mcp_servers.tia-gateway]`（单引号字面量 + `startup_timeout_sec = 120`，保留 `.env` 子节） |
| **WorkBuddy** (`workbuddy`) | `%USERPROFILE%\.workbuddy-ai\mcp.json` | 合并 `mcpServers.tia-gateway`，同步 skills |
| **opencode** (`opencode`) | `%XDG_CONFIG_HOME%\opencode\opencode.json` / `%USERPROFILE%\.config\opencode\opencode.json` | 合并 `mcp.servers.tia` |
| **DeepSeek Harness** (`dsh`) | `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` | 原地更新或追加 `id: mcp-tia-gateway` |

**改之前都会备份**成 `原文件名.bak-时间戳`，改坏了直接改回去；**路径已一致时不会产生多余备份**。

安装完看输出：
- `[完成] xxx 已自动配置` / `[完成] xxx 已更新` → 这个客户端好了
- `[跳过] xxx 路径已一致，跳过（未产生备份）` → 你之前已配好且路径一致，未动它
- `[跳过] xxx 未安装或未找到配置` → 你机器上没有这个客户端；若后续新装或想强行初始化，跑 `gateway\runtime\node.exe install.js --host <id>` 或对照 `生成的配置\使用说明.txt` 手动合并即可

> ⚠️ **WorkBuddy 多一道手续**：它不会自动启用新加的 MCP，必须在界面里点一次「信任」。
> 左侧栏「专家技能连接器」→ 右上角「自定义连接器」→ 找到 `tia-gateway` → 点「信任」。
> 不点的话，AI 在对话里看不到 `d_*` 工具（有些模型会自己写客户端绕过去，但很慢）。

<details>
<summary>手动配置说明（一般用不到，点开看）</summary>

1. 打开 `生成的配置\使用说明.txt`，里面已经按你的实际解压路径生成了所有 10 份模板文件与目标路径对照表：
   - **Antigravity**：合入 `%USERPROFILE%\.gemini\config\mcp_config.json`（请勿放入 Gemini CLI 的 `settings.json`）
   - **Claude Desktop / Claude Code / Cursor / Gemini CLI / WorkBuddy**：合入对应 `mcpServers["tia-gateway"]`
   - **VS Code**：合入 `%APPDATA%\Code\User\mcp.json` 的 `"servers"` 键（`type: "stdio"`）
   - **Codex**：将 `生成的配置\codex-config.toml` 的 `[mcp_servers.tia-gateway]` 合入 `%USERPROFILE%\.codex\config.toml`（注意 Windows 路径必须用单引号字面量）
   - **opencode**：合入 `opencode.json` 的 `mcp.servers.tia`（可在 opencode 里跑 `opencode debug paths` 确认路径）
   - **DeepSeek Harness**：将 `生成的配置\dsh-cordis.patch.yml` 合入 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`，改完**必须重启 DSH**
2. 或者直接用命令行指定生成：
   `gateway\runtime\node.exe install.js --host <宿主id>`

</details>

## 第 3 步：打开博途

- 启动 TIA Portal（V20 或 V21）
- 打开一个工程，或者新建一个

**第一次连接会弹西门子的 Openness 授权窗口** —— 这是正常的安全机制，不是报错。
看清程序路径（应该是你解压目录下的 `upstreams\a\tia-portal-mcp.exe` 或 `upstreams\b\runtime\v20\TiaMcpServer.exe`），点「**是，全部接受**」，确认 UAC。

> 这一步必须人工点，AI 不会替你点，也不该替你点。

## 第 4 步：让 AI 试一下

在 AI 里说：

```text
用 D 检查一下环境
```

它应该调 `d_doctor`（**默认快速零拉起，不会抢端口也不会拉起 TIA**），返回类似这些检查项：

```text
mode: fast
checks:
  exclusive-lock: ok    pending-recovery: ok   port-8000: free/ok
  tia-installed: ok     openness-group: ok     running-portals: ...
  upstream-a: ok        upstream-b-v20: ok     upstream-b-v21: ok
  upstream-c: false (未安装)
```

只有真正想实起上游 A 深探时，才让 AI 传 `d_doctor({ deep: true })`。若本机已有另一个客户端或旧服务占着 8000 端口，`port-8000` 会准确显示占用者的状态、PID 与进程路径。

然后试：

```text
用 D 连 V20，看一下工程里有什么
```

## V20 和 V21 的差异（用 V21 必看）

网关会自动按你装的版本选运行时，不用手动切。但两者有实质差别，下载和 HMI 尤其明显：

| 项 | V20 | V21 |
|---|---|---|
| 上游 B 运行时 | `upstreams/b/runtime/v20` | `upstreams/b/runtime/v21`（包里都有） |
| 下载时 `target_interface` 填什么 | **上游 A / B 均填 PLC 的 IP**，如 `192.168.0.1` | **上游 A 填接口名**（如 `PN/IE_1` 或 `1 X1`）；**上游 B 仍填 PLC 的 IP**（映射到 `targetIpAddress`） |
| Openness 目录结构 | `PublicAPI\V20\` 下直接是 DLL | `PublicAPI\V21\net48\` 多一层 |
| HMI 连接 | 只能 non-integrated，变量只能绑**绝对地址** | 可以 integrated，能绑**符号名** |
| 变量表重命名 | Openness 不支持，只能在 TIA 界面里改 | 支持 |
| 上游 C（内容哈希 / 细粒度跨引用） | 跑不了 | 可以装，需 .NET 10 SDK + `dotnet tool install -g TiaMcpServer` |

**最容易踩的是第二条（需区分上游 A 和 B）：**
- 走 **上游 A** 时：V21 把 IP 填进 `target_interface` 会报"找不到接口"，照报错信息填可用接口名（如 `PN/IE_1` / `1 X1`）即可；
- 走 **上游 B** 时：`d_download` 固定将 `target_interface` 映射为 `targetIpAddress`，因此 **V20 和 V21 一律填 PLC 的 IP**（如 `192.168.0.1`，填 `'PN/IE_1'` 会报找不到匹配 IP 路由）。

> 提示：`skills/siemens-v20-ops` 里有一部分规则是 V20 专属的（比如"HMI 只能绑绝对地址"）。
> 用 V21 时这些不适用，以 `skills/tia-portal-ops` 和实际报错为准。

## 排错表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `d_doctor` 提示 `port-8000` 被占用 | 8000 端口正被其他进程或外部 MCP 占用 | 先看 `d_doctor` 返回的 `PID` 与进程路径；如确定要接管外部运行中的 MCP A，可在 `gateway/d.config.json` 的 `upstreams.a` 下配 `"adoptExternal": true`；若是无关进程，关掉它 |
| `d_doctor({ deep: true })` 启动 A 失败 | 上游 A 起不来或端口被 Windows 排除 | 检查是否命中系统保留端口 `excluded_by_os`，或双击 `scripts\启动TIA-MCP服务.bat` 看报错 |
| `openness-group: false` | 不在 Openness 组 | 加组 + 注销重登 |
| `tia-installed` 只显示 V16 | 没装 V20/V21 | 装 V20 或 V21（V15–V19 也可直接走 `d_connect` 自动路由到 A） |
| AI 说"另一个网关实例正在占用 TIA" | 另一个 AI 客户端正连着 | 关掉那个客户端的会话，或等 5 分钟锁自动过期 |
| `d_save` / `d_finish` 报被 `pending_recovery.json` 阻断 | 上一次 `d_write_block` 写块与自动回滚均失败 | 优先看响应里的 `manualRecovery`：重新对故障块执行一次 `d_write_block` 写通（自动清标），或手动导入 `outbox` 中的备份 XML 后在 `d_doctor` / `d_save` 传 `clear_pending_recovery: true`；确需强存磁盘才传 `allow_dirty_save: true` |
| WorkBuddy 里 AI 说"没有 MCP 工具" | 新加的 MCP 没点信任 | 见第 2 步的 ⚠️ 说明，去连接器页面点「信任」 |
| 连接时弹西门子窗口 | Openness 首次授权 | 人工点「是，全部接受」 |
| `d_read_block` 传 `format: "s7dcl"` 报 `EngineeringNotSupportedException` | V20 下 `ExportAsDocuments` 不支持 **SCL** 块 | 改用 `format: "xml"` 读完整接口+代码，或重调时加 `fallback_to_xml: true` |
| `d_read_block` 传 `format: "xml"` 找不到子组里的块 | B 的原生 `ExportBlock(xml)` 不传 `group` 时只查根目录（与 `ExportAsDocuments` 相同） | 显式传入 `group: "子组路径"`（如 `"工位A/子功能"`）；若读 LAD 块 `s7dcl` 会自动检索子组 |
| `d_read_block`（无 format）显示 `(无 FlgNet / 不支持的语言)` | 那个 LAD 网络里只有块调用（Call 指令） | 正常现象，LAD 块可传 `format: "s7dcl"`（或 `xml`）导出查看 |
| 编译报"password does not comply" | Unified HMI 默认密码策略 | 在 TIA 里改运行时用户配置，跟网关无关 |
| 下载报"no PG/PC interface matches" | 网卡名写错 | 错误信息里会列出全部可用网卡，照着填 |
| PLCSIM Advanced V7.0 下载报「检测到不兼容的设备」/ 无法建连 | 本机其他网卡占用了 `192.168.0.0/24`（TIA 默认 `192.168.0.1` PN-DCP 发现后 TCP 路由走错），或虚拟网卡仍为 `169.254.x.x/16` APIPA | 在**管理员终端**用 `netsh` 把 `Siemens PLCSIM Virtual Ethernet Adapter` 配到不冲突冷门网段（如 `192.168.250.1/24`），并把 PLC IP 设到同网段 |
| `plcsim-adv-bridge` CLI 退出后实例消失 / 退回 `Softbus`、S7 102 读 DB 失败 | 短生命周期 CLI 退出后无常驻持有者会释放实例并退回 `Softbus`；S7 102（`Sharp7`）要求 `TCPIPSingleAdapter` + 非优化 DB + `Put/Get` | 若需持久运行，保持 `--mcp` 常驻或打开 PLCSIM GUI；读 DB 需关闭块属性"优化的块访问"并启用 `Put/Get`（V20 FW V4.0 CPU 还会默认启用机密组态保护、安全通信与 UMAC 访问控制） |

## 想自己验证网关好不好使

建议用隔离的临时运行目录执行离线自检（不会干扰本机 8000 端口，也不要求 TIA 正在运行）：

```powershell
$env:D_RUNTIME_DIR = "$env:TEMP\tia_smoke"
<TIA-MCP 安装目录>\gateway\runtime\node.exe <TIA-MCP 安装目录>\gateway\smoke-test.js
Remove-Item Env:D_RUNTIME_DIR -ErrorAction SilentlyContinue
```

脚本会运行全部纯函数单测、`F1–F14` Mock HTTP（`127.0.0.1:0`）与 Mock B 故障注入矩阵以及 B 离线检查，并在末尾打印精确的 `通过/总数` 统计。全过说明网关本身工作正常。
