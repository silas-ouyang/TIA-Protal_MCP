# 快速开始

> **这是一份说明文档，不是程序。** 双击会用你机器上的 Markdown 编辑器打开（VSCode / Typora / WorkBuddy 等），
> 读它就行，**不会执行任何东西**。
>
> **真正的安装动作是双击包根目录的 `安装.bat`。**

目标：15 分钟内让 AI 能读写你的博途工程。

---

## 第 0 步：确认前置条件

在 PowerShell 里跑这条，看当前用户在不在 Openness 组：

```powershell
whoami /groups | Select-String "Openness"
```

- 有输出 → 通过
- 没输出 → 加组：`计算机管理 → 本地用户和组 → 组 → Siemens TIA Openness → 添加 → 输入你的用户名`
  然后**注销重登**（不重登不生效）

---

## 第 1 步：解压 + 安装

1. 解压到固定位置，例如 `D:\TIA-MCP\`，**路径不要含空格**
2. 双击 `安装.bat`
3. 看到 `安装完成，8 项检查全过` 就对了

安装脚本做了三件事：
- 把 `skills/` 下四个 skill 复制到 `%USERPROFILE%\.agents\skills\` 和 `%USERPROFILE%\.workbuddy-ai\skills\`
- **自动把 MCP 配置写进你机器上已装的 AI 客户端**（opencode / WorkBuddy / DSH），改前自动备份
- 在 `生成的配置/` 下留一份模板，给没自动配上的客户端用

---

## 第 2 步：安装脚本已经帮你配好了

**这一步通常不用做任何事。** `安装.bat` 会自己去你机器上找三个客户端，找到就自动合并配置：

| 客户端 | 它会改的文件 | 行为 |
|---|---|---|
| opencode | `%USERPROFILE%\.config\opencode\opencode.json`（或 `%XDG_CONFIG_HOME%\opencode\`） | 合并 `mcp.servers.tia`，不动你别的配置 |
| WorkBuddy | `%USERPROFILE%\.workbuddy-ai\mcp.json` | 合并 `mcpServers.tia-gateway` |
| DeepSeek Harness | `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` | 在末尾追加一段 |

**改之前都会备份**成 `原文件名.bak-时间戳`，改坏了直接改回去。

安装完看输出：
- `[完成] xxx 已自动配置` → 这个客户端好了
- `[跳过] xxx 里已经有 tia 配置` → 你之前配过，它没动
- `[跳过] xxx 没装或没找到配置` → 你机器上没有这个客户端，或者它的配置在非标准位置

**只有出现第三种情况、而你确实要用那个客户端时**，才需要手动处理：模板在 `生成的配置\` 里，
按下面的说明放进去。

> ⚠️ **WorkBuddy 多一道手续**：它不会自动启用新加的 MCP，必须在界面里点一次「信任」。
> 左侧栏「专家技能连接器」→ 右上角「自定义连接器」→ 找到 `tia-gateway` → 点「信任」。
> 不点的话，AI 在对话里看不到 `d_*` 工具（有些模型会自己写客户端绕过去，但很慢）。
> opencode 和 DSH 没有这一步，重启即生效。

<details>
<summary>手动配置说明（一般用不到，点开看）</summary>

**opencode**：把 `生成的配置/opencode.json` 里的 `mcp.servers.tia` 合并进你的 `opencode.json`。
不确定配置在哪的话，在 opencode 里跑 `opencode debug paths`，看 `config` 那一行。

**WorkBuddy**：把 `生成的配置/workbuddy-mcp.json` 里的 `mcpServers.tia-gateway` 合并进
`%USERPROFILE%\.workbuddy-ai\mcp.json`。

**DeepSeek Harness**：把 `生成的配置/dsh-cordis.patch.yml` 的内容追加到
`%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 末尾（注意 YAML 缩进）。
改完**必须重启 DSH**，它的热重载不会重连 stdio 类型的 MCP。

</details>

---

## 第 3 步：打开博途

- 启动 TIA Portal（V20 或 V21）
- 打开一个工程，或者新建一个

**第一次连接会弹西门子的 Openness 授权窗口** —— 这是正常的安全机制，不是报错。
看清程序路径（应该是你解压目录下的 `upstreams\a\tia-portal-mcp.exe`），点「**是，全部接受**」，确认 UAC。

> 这一步必须人工点，AI 不会替你点，也不该替你点。

---

## 第 4 步：让 AI 试一下

在 AI 里说：

```
用 D 检查一下环境
```

它应该调 `d_doctor`，返回类似：

```
exclusive-lock:true  upstream-a:true  tia-installed:true
openness-group:true  upstream-b:true  upstream-c:false
```

全 true（除了 upstream-c）就说明通了。

然后试：

```
用 D 连 V20，看一下工程里有什么
```

## V20 和 V21 的差异（用 V21 必看）

网关会自动按你装的版本选运行时，不用手动切。但两者有实质差别，下载和 HMI 尤其明显：

| 项 | V20 | V21 |
|---|---|---|
| 上游 B 运行时 | `upstreams/b/runtime/v20` | `upstreams/b/runtime/v21`（包里都有） |
| 下载时 `target_interface` 填什么 | **PLC 的 IP**，如 `192.168.0.1` | **接口名**，如 `PN/IE_1` |
| Openness 目录结构 | `PublicAPI\V20\` 下直接是 DLL | `PublicAPI\V21\net48\` 多一层 |
| HMI 连接 | 只能 non-integrated，变量只能绑**绝对地址** | 可以 integrated，能绑**符号名** |
| 变量表重命名 | Openness 不支持，只能在 TIA 界面里改 | 支持 |
| 上游 C（内容哈希 / 细粒度跨引用） | 跑不了 | 可以装，需 .NET 10 SDK + `dotnet tool install -g TiaMcpServer` |

**最容易踩的是第二条。** V21 上把 IP 填进 `target_interface` 会报"找不到接口"；
报错信息里会列出可用接口名，照着填 `PN/IE_1` 这种就行。

> 提示：`skills/siemens-v20-ops` 里有一部分规则是 V20 专属的（比如"HMI 只能绑绝对地址"）。
> 用 V21 时这些不适用，以 `skills/tia-portal-ops` 和实际报错为准。

## 常用话术

| 你想干的事 | 这么说 |
|---|---|
| 看工程结构 | 用 D 读一下工程树 |
| 读某个块 | 用 D 把 FB_电机控制 这个块读出来看看 |
| 写新块 | 用 D 给 PLC_1 写一个三段式电机启停，写进 OB1 |
| 改已有块 | 用 D 把 FC_1 改成……（AI 会先读、再改、再编译） |
| 编译 | 用 D 编译一下 PLC_1 |
| 收尾保存 | 用 D 收尾（离线→编译→保存） |
| 下载到 PLC | 用 D 下载到 PLC，网卡是 xxx，IP 是 192.168.0.1（**必须你自己给参数**） |

## 排错表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `d_doctor` 里 `upstream-a:false` | 上游 A 起不来 | 手动双击 `scripts\启动TIA-MCP服务.bat` 看报错 |
| `openness-group:false` | 不在 Openness 组 | 加组 + 注销重登 |
| `tia-installed` 只显示 V16 | 没装 V20/V21 | 装 V20 或 V21 |
| AI 说"另一个网关实例正在占用 TIA" | 另一个 AI 客户端正连着 | 关掉那个客户端的会话，或等 5 分钟锁自动过期 |
| WorkBuddy 里 AI 说"没有 MCP 工具" | 新加的 MCP 没点信任 | 见第 2 步的 ⚠️ 说明，去连接器页面点「信任」 |
| 连接时弹西门子窗口 | Openness 首次授权 | 人工点「是，全部接受」 |
| 写块报"编码错误" | `.scl` 中文没 BOM | 网关会自动加 BOM，若仍报错改用 `format: 's7dcl'` |
| 读块显示"(无 FlgNet / 不支持的语言)" | 那个网络里只有块调用（Call 指令） | 正常现象，改用 `ExportAsDocuments` 导 `.s7dcl` 看 |
| 编译报"password does not comply" | Unified HMI 默认密码策略 | 在 TIA 里改运行时用户配置，跟网关无关 |
| 下载报"no PG/PC interface matches" | 网卡名写错 | 错误信息里会列出全部可用网卡，照着填 |

## 日志在哪

```
<TIA-MCP 安装目录>\gateway\runtime\d.log
```

每次调用一行 JSON：时间、进程号、上游、工具、耗时、成败、错误。排查问题先看这个。

## 想自己验证网关好不好使

```cmd
<TIA-MCP 安装目录>\gateway\runtime\node.exe <TIA-MCP 安装目录>\gateway\smoke-test.js
```

35 项断言。**跑之前先把其他连着 TIA 的客户端关掉**——自检会临时起两个上游实例，
如果另一个网关正占着 TIA，会卡在 Openness 上（这正是独占锁在起作用）。
TIA 本身开着没关系。全过说明网关本身没问题。
